# Контент игры

Здесь лежит всё, что пишется словами, а не кодом: кейсы, регламенты, справочники, персонажи.
Файлы в формате YAML можно править прямо на сайте GitHub (иконка карандаша).
При каждой сборке `npm run content:check` проверяет, что всё сходится.

> Формат — черновик. Сейчас в нём один пример, `cases/day1/bec.yaml`.
> Остальные кейсы из прототипа переносятся сюда на следующем шаге.

## Файлы

- `directory.yaml` — регламенты, угрозы, сотрудники, контрагенты, ПО
- `cases/dayN/<id>.yaml` — один кейс на файл

## Улики

Поле, по которому можно кликнуть в режиме инспекции, пишется так: `[[ключ|текст]]`.

```yaml
body: |
  По всем вопросам звоните мне напрямую.
  [[bec.phone|+7 499 113-08-52]]
```

Противоречие — пара ключей и текст находки:

```yaml
evidence:
  - [bec.phone, ref.ts.phone, Телефон в подписи не совпадает с телефоном из договора]
```

Ключи справочника начинаются с `ref.`, регламентов — с `rule.`, угроз — с `threat.`.

## Слои «Изучить»

Блок со скрытой информацией помечается `layer:` с id слоя из списка `layers`. Он открывается за указанные минуты смены.

## Исходы

| Значение  | Что значит                                 | Очки |
|-----------|--------------------------------------------|------|
| `best`    | лучшее решение                             | +15  |
| `ok`      | верно                                      | +10  |
| `partial` | угроза остановлена, но не до конца         | +10, пояснение |
| `false`   | ложная блокировка легитимного              | лояльность −20 |
| `miss`    | атака пропущена                            | −25  |
| `policy`  | пропущено вопреки регламенту               | −10  |

## Чек-лист нового кейса

- [ ] Решение следует из того, что есть на экране и в справочнике, а не из знания инцидента
- [ ] У атаки есть легитимный двойник
- [ ] Указан слой, где лежит разгадка (`key`)
- [ ] В разборе — что случилось на самом деле и источник
