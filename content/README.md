# Контент игры

Здесь лежит всё, что пишется словами, а не кодом: кейсы, регламенты, справочники, сюжет.
Файлы в YAML можно править прямо на сайте GitHub (иконка карандаша). Каждая правка проходит проверку
`npm run content:check`, и если что-то не сходится, pull request покажет, что именно.

```
content/
├─ world/
│  ├─ rules.yaml        регламенты и угрозы бюллетеня, лимит эскалаций
│  ├─ people.yaml       кадровая система, руководители, внешние персонажи
│  ├─ contractors.yaml  контрагенты, ПО и хэши, матрица доступа
│  └─ campaign.yaml     смены, утренние новости, бюджет, покупки, итог сквозной атаки
└─ cases/
   ├─ day1/  9 кейсов
   ├─ day2/  7 кейсов
   └─ day3/  8 кейсов (часть приходит только при определённых решениях)
```

## Улики

Поле, по которому можно кликнуть в режиме инспекции, пишется так: `[[ключ|текст]]`.

```yaml
body: |
  По всем вопросам звоните мне напрямую.
  [[bec.phone|+7 499 113-08-52]]
```

Противоречие — два ключа и текст находки:

```yaml
evidence:
  - ["bec.phone", "ref.ts.phone", "Телефон в подписи не совпадает с телефоном из договора"]
```

Ключи справочника начинаются с `ref.`, регламентов — с `rule.`, угроз — с `threat.`.
Проверка следит, чтобы поле справочника уже было видно в этой смене: в первой смене нельзя ссылаться
на подрядчика, который появляется только во второй.

## Кейс

```yaml
id: bec                  # совпадает с именем файла
day: 1                   # смена
order: 3                 # порядок в очереди
when: { flags: { chain: foothold } }   # необязательно: кейс приходит только при условии
kind: email              # email | call | alert
type: Письмо             # подпись в очереди: Письмо, VPN, EDR, MFA, Доступ, Облако, IDS, AD, Звонок
title: ...
truth: attack            # attack | legit | policy (легитимно, но запрещено регламентом)
outcomes: { allow: miss, block: best, escalate: ok }
requires_call: true      # необязательно: без звонка верное решение считается нарушением
par: 0                   # минуты изучения, при которых дают бонус «экономно»
partial_note: ...        # пояснение для исхода partial
loyalty_cost: { block: 10 }   # необязательно: верное, но непопулярное решение
fx:                      # необязательно: какие флаги выставляет решение
  allow: { chain: foothold }
```

Поверхность — то, что видно сразу, — задаётся блоком по типу:

- `email`: имя и адрес отправителя, тело, цитата, вложение, ссылка, отметка «сотрудник сообщил о фишинге»;
- `phone_call`: линия, номер по АТС, заметка, реплики `[кто, текст]`;
- `alert`: важность, заголовок, строка сводки.

`ticket` — строка тикета внизу объекта.

### Слои «Изучить»

```yaml
layers:
  - { id: props, label: Свойства письма, cost: 10 }
  - { id: sandbox, label: Песочница для вложения, cost: 45, needs: sandbox }   # нужна покупка
blocks:
  - layer: props
    headers: [["Reply-To", "..."]]   # или table: [[подпись, значение]], или note: текст
  - layer: sandbox
    at: bottom                       # показать внизу, под вложением
    note: ...
```

Адрес отправителя (`email.from_addr.layer`), номер по АТС (`phone_call.number.layer`)
и адрес ссылки (`email.link.layer`) тоже могут быть скрыты слоем.

### Исходы

| Значение      | Что значит                             | Последствия        |
|---------------|----------------------------------------|--------------------|
| `best`        | лучшее решение                         | +15                |
| `ok`          | верно                                  | +10                |
| `partial`     | угроза остановлена, но не до конца     | +10, пояснение     |
| `false_block` | заблокировано легитимное               | лояльность −20     |
| `miss`        | атака пропущена                        | −25                |
| `policy`      | пропущено вопреки регламенту           | −10                |

Проверка следит за логикой: у атаки пропуск всегда `miss`, у легитимного блокировка — `false_block`.

### Проверка по второму каналу и разбор

```yaml
call:
  label: Позвонить Павлову по номеру из договора
  person: pavlov          # id из people.yaml — для портрета
  text: "С. Павлов: «Реквизиты не менялись»."
  finding: Контрагент не подтвердил смену реквизитов   # добавляется в находки
key: Где была разгадка — показывается в разборе.
debrief:
  label: Основано на реальном инциденте   # или «Легитимный двойник», «Ситуация из практики»
  name: Дело Римасаускаса против Google и Facebook (2013–2015)
  text: Что было на самом деле и источник.
```

## Условия

Используются в `when` у кейсов, новостей и итогов атаки:

```yaml
when:
  flags: { chain: foothold }        # флаги равны
  not_flags: { beacon: escalated }  # флаги не равны
  upgrade: nm                       # покупка сделана
  no_upgrade: nm                    # покупки нет
```

Проверка следит, чтобы флаг выставлялся раньше, чем его проверяют.

## Подводные камни YAML

- Если текст содержит двоеточие с пробелом (`Re: Акт`), запятую внутри `[...]` или начинается с кавычки «, возьмите его в двойные кавычки.
- `false`, `true`, `yes`, `no` без кавычек YAML считает логическими значениями.
- Отступы — только пробелы.

## Чек-лист нового кейса

- [ ] Решение следует из того, что есть на экране и в справочнике, а не из знания инцидента
- [ ] У атаки есть легитимный двойник
- [ ] В `key` сказано, в каком слое лежит разгадка
- [ ] В разборе — что случилось на самом деле и источник
